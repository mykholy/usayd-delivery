# Codex / engineering agents — mandatory repository instructions

Project: **Smart Quran Academy**. Source pack is product specification **not running source code**. Read `README_AR.md`, `00_START_HERE/EXECUTION_ORDER.md`, `02_REQUIREMENTS/SRS.md`, `04_ENGINEERING/openapi.yaml`, `07_QUALITY_SECURITY/TEST_AUTOMATION_STRATEGY_v1.1.md` before implementation.

## Objective
Create maintainable, secure, production-quality modular Laravel API and web/Flutter clients through phase gates. Make real code changes, run real tests, report exact evidence. Do not invent implementation/test results or change specs silently.

## Critical constraints
1. Every account is learner-first. For minors enforce verified consent/age rules and safe access; never require adult guardian UI for all learners.
2. Auth decisions live server-side; check `role + resource ownership + purpose + consent state` on every handler/job/webhook. Use explicit deny-by-default policies.
3. Never trust AI-generated Quran verses as canonical; content requires licensed, verified data and academic reviewer. AI may propose, teacher signs.
4. Audio transcription/AI policy analysis must respect purpose-specific consent and retention; no hidden recording and no automatic punishment.
5. External Meet/Zoom cannot be assumed to support raw audio, custom UI or bot moderation. All providers implement capability query with fail-closed feature gates.
6. Money in integer minor units, ISO currency; immutable ledgers and idempotent webhook processing. Compensation effective-dated with immutable pay rule snapshots.
7. Every content mutation audited; privacy-restricted data must not appear in logs/analytics/third-party telemetry.
8. No seeded real user info, fabricated teacher credentials, sample Quran verses generated by a model, or production credentials.
9. Never run destructive migration/seed or production deploy without approved plan and backup; never auto-submit/apply real payments.

## Engineering default
- First decision: ADR for exact supported versions at build time (Laravel 13 is available in Nov 2026; verify PHP support with official docs), DB MySQL 8+, Redis, queues, storage, frontend, Flutter stable; pin versions to lockfiles.
- Modular monolith organized by domain; API `/api/v1`; typed OpenAPI; stable IDs; outbox; UTC timestamps; IANA timezone; explicit errors and correlation IDs.
- Ownership: `/backend`, `/web`, `/mobile`, `/infra`, `/docs`, `/tests`; if creating repo from scratch write initial scaffold and commands in README.
- Use REST and consistent problem+json; verify request/response/contract tests. Do not substitute generic DTOs in production.

## Task execution (one Jira issue at a time)
A. Select a Ready issue with Requirement ID, API, UX, tests and dependencies. B. Explain scope/risks and list affected files. C. Implement minimal vertical slice with migrations, policies, requests, resources, unit and feature tests, UI states and events. D. Execute tests/lint/static security checks and report command outputs. E. Update traceability, OpenAPI, ADR and changelog. F. Create PR/commit as authorized, keep main protected. G. If blocked, produce exact blocker and safe partial output, never claim Done.

## Completion evidence
Each issue must contain `Implemented paths`, `Migration impact`, `API schema diff`, `Security reasoning`, `Tests added`, `Commands/results`, `Screens/UX IDs`, `Known limitations`, `Rollback steps`, `Reviewer signoff`. Security/academic/legal sensitive issues require human approval.

## Hard stop gates
Consent missing or withdrawn; unresolved P0/P1 incident; Quran corpus unverified; payment double-charge; cross-tenant/learner data leakage; race causing duplicate booking; unknown video capability used as guaranteed; invalid signing secrets; contest score finalized by AI alone: mark Blocked and do not deploy.
