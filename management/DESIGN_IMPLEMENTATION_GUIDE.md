## Work-item checklist

1. Fetch the exact `planning/tasks/USYD-T####.md` and Jira key, dependencies, approval gates and current status. Locate all linked screens/actions/FRs/API operations in `coverage/*.csv` and original mapping files. Read the actual referenced screen MD, AR/EN HTML and Canvas before coding, including every state and responsive variant. Read original FRs, permissions, business rules, data model and relevant journey acceptance cases. Never infer backend requirements solely from prototype links.
2. Match canonical route, components, tokens, RTL/LTR, Auto/Light/Dark and Kids/Professional/Simple when relevant. Follow six states: loading, empty, error, no permission, offline, success. Verify 1440/768/390 and other required sizes, 44px targets, keyboard/focus, reduced motion, WCAG 2.2 AA. Preserve locale/country/timezone independence; no fake production success. Only render owner-supplied authentic content or hide unavailable slots.
3. Keep Laravel/Next.js/Flutter repos separate. No Flutter implementation or Jira status mutation by full-stack sync operator; read-only mobile status is allowed. Reuse shared canonical UI components (pricing UX-GLOB-002, settings UX-SUP-010 subject to technical review); do not build duplicate routes independently. Keep minors limited; no paid/recording/AI/Quran processing without signed gates. Use integer minor units, UTC, IANA zones.
4. Verify server authorization, actual contract compatibility, real tests, visual checks and relevant negative states. Write exact evidence (PR/head, CI links, tests, screenshots where available). Update Jira with confirmed status and [live snapshot](../automation/LIVE_DELIVERY_STATE.json) after work. If a gate remains, keep it open. Source-level decisions are immutable; use supplemental [owner decision register](OWNER_DECISION_REGISTER_2026-11-26.md).
